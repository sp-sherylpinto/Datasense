Introduction to SQL

SQL (Structured Query Language) is how you talk to a database. In DataSense Pro, every file you upload becomes a database table, and SQL is the most powerful way to explore it.

ℹ️

DataSense Pro only allows SELECT queries. You can read and explore any data, but you cannot modify, delete, or insert records. This keeps your data safe.

How SQL Works

Think of SQL as asking questions to your data. A basic SQL query has three parts:

Anatomy of a SQL query
SELECT  column1, column2        -- WHAT you want to see
FROM    datasets.ds_your_table   -- WHERE the data lives
WHERE   amount > 10000          -- WHICH rows to include
LIMIT   100;                      -- HOW MANY rows to return

SQL is like a question

Instead of: "Show me all payments over ₹10,000 from the payments table"

You write: SELECT * FROM datasets.ds_payments WHERE amount > 10000

💡

Tip: SQL keywords (SELECT, FROM, WHERE) are not case-sensitive. select works the same as SELECT. By convention we write keywords in UPPERCASE to make queries easier to read.

Your Data & Schema

Every file you upload in DataSense Pro becomes a dedicated table in PostgreSQL. Here's how to find and use them.

Where Your Data Lives

All uploaded datasets are stored in a PostgreSQL schema called datasets. Each file gets its own table with a unique name:

Table naming pattern
datasets.ds_a3f7c291b4e812d0
-- ↑ schema   ↑ unique identifier (hex)
💡

Finding your table name: In the SQL Workbench, click any dataset in the left panel. The editor will auto-populate with the correct table name. You can also see it in the "Saved Datasets" section on the Data Source tab.

Listing Your Tables

See all your datasets
SELECT
    original_filename,
    table_name,
    row_count,
    file_type,
    created_at
FROM    datasets
ORDER BY created_at DESC;

Exploring a Table's Structure

See column names and types for a table
SELECT
    column_name,
    data_type,
    is_nullable
FROM   information_schema.columns
WHERE  table_schema = 'datasets'
  AND  table_name   = 'ds_your_table_id_here'
ORDER BY ordinal_position;

SELECT Basics

SELECT is how you retrieve data. It's the only statement you'll use in DataSense Pro.

Select All Columns

All columns, first 100 rows
SELECT *
FROM   datasets.ds_your_table
LIMIT  100;
💡

* means "all columns". Always add LIMIT when exploring large tables — the Workbench caps at 500 rows by default.

Select Specific Columns

Pick only the columns you need
SELECT
    vendor_name,
    invoice_date,
    amount,
    status
FROM  datasets.ds_your_table
LIMIT 200;

Rename Columns with Aliases

Give columns friendlier names in results
SELECT
    vendor_name    AS "Vendor",
    invoice_date   AS "Invoice Date",
    amount         AS "Amount (₹)"
FROM  datasets.ds_your_table;

Calculated Columns

Create a new column from a calculation
SELECT
    vendor_name,
    amount,
    tax_amount,
    amount + tax_amount        AS total_payable,
    amount * 0.18              AS gst_18_percent,
    amount / 100000            AS amount_in_lakhs
FROM  datasets.ds_your_table;

Count Rows

How many rows are in your table?
SELECT COUNT(*) AS total_rows
FROM   datasets.ds_your_table;

Remove Duplicates with DISTINCT

Unique values in a column
-- All unique vendor names
SELECT DISTINCT vendor_name
FROM   datasets.ds_your_table
ORDER BY vendor_name;

-- Count of unique vendors
SELECT COUNT(DISTINCT vendor_name) AS unique_vendors
FROM   datasets.ds_your_table;
Filtering with WHERE

WHERE narrows down which rows to include in your results. Think of it as applying a filter to your data.

Comparison Operators

OperatorMeaningExample
=Equal tostatus = 'Active'
!= or <>Not equal tostatus != 'Cancelled'
>Greater thanamount > 100000
<Less thanamount < 500
>=Greater than or equalamount >= 50000
<=Less than or equalamount <= 99999
Basic WHERE examples
-- Transactions above 1 lakh
SELECT * FROM datasets.ds_your_table
WHERE  amount > 100000;

-- Only a specific vendor
SELECT * FROM datasets.ds_your_table
WHERE  vendor_name = 'ABC Enterprises Pvt Ltd';

AND / OR — Combining Conditions

Multiple conditions
-- AND: both conditions must be true
SELECT * FROM datasets.ds_your_table
WHERE  amount > 50000
  AND  status = 'Paid';

-- OR: either condition can be true
SELECT * FROM datasets.ds_your_table
WHERE  status = 'Pending'
  OR   status = 'Overdue';

-- Combining AND / OR — use brackets to be explicit
SELECT * FROM datasets.ds_your_table
WHERE  amount > 100000
  AND  (status = 'Pending' OR status = 'Overdue');

IN — Match a List of Values

Filter by multiple values at once
-- Specific status codes
SELECT * FROM datasets.ds_your_table
WHERE  status IN ('Pending', 'Overdue', 'Disputed');

-- Exclude certain vendors
SELECT * FROM datasets.ds_your_table
WHERE  vendor_name NOT IN ('Internal Transfer', 'Opening Balance');

BETWEEN — Range of Values

Values within a range (inclusive)
-- Amounts between 50,000 and 5,00,000
SELECT * FROM datasets.ds_your_table
WHERE  amount BETWEEN 50000 AND 500000;

-- Date range (financial year)
SELECT * FROM datasets.ds_your_table
WHERE  invoice_date BETWEEN '2024-04-01' AND '2025-03-31';

LIKE — Pattern Matching

Find text that matches a pattern
-- % matches any sequence of characters
-- _ matches exactly one character

-- Names starting with "Sharma"
SELECT * FROM datasets.ds_your_table
WHERE  vendor_name LIKE 'Sharma%';

-- Names containing "Trading"
SELECT * FROM datasets.ds_your_table
WHERE  vendor_name LIKE '%Trading%';

-- Case-insensitive: use ILIKE instead
SELECT * FROM datasets.ds_your_table
WHERE  vendor_name ILIKE '%pvt ltd%';
Sorting with ORDER BY

ORDER BY controls the sequence in which rows appear in your results.

Basic Sorting

Sort results
-- Largest amounts first (descending)
SELECT * FROM datasets.ds_your_table
ORDER BY amount DESC;

-- Earliest dates first (ascending — this is the default)
SELECT * FROM datasets.ds_your_table
ORDER BY invoice_date ASC;

-- Sort by vendor name, then by amount within each vendor
SELECT * FROM datasets.ds_your_table
ORDER BY vendor_name ASC, amount DESC;

Top N Records

Find the largest transactions
-- Top 20 largest transactions
SELECT
    vendor_name,
    invoice_date,
    amount
FROM  datasets.ds_your_table
ORDER BY amount DESC
LIMIT 20;
💡

Audit tip: Always sort by amount DESC when starting an audit review — the largest transactions are usually the highest risk and deserve the most attention.

Dataset summary statistics
SELECT
    COUNT(*)                        AS total_transactions,
    ROUND(SUM(amount), 2)          AS total_value,
    ROUND(AVG(amount), 2)          AS average_amount,
    MIN(amount)                      AS smallest,
    MAX(amount)                      AS largest,
    COUNT(DISTINCT vendor_name)     AS unique_vendors
FROM  datasets.ds_your_table;
GROUP BY & HAVING

GROUP BY aggregates rows that share the same value in a column — e.g., totals per vendor, counts per month.

GROUP BY

Total amount per vendor
SELECT
    vendor_name,
    COUNT(*)              AS invoice_count,
    ROUND(SUM(amount), 2) AS total_paid,
    ROUND(AVG(amount), 2) AS avg_invoice
FROM   datasets.ds_your_table
GROUP BY vendor_name
ORDER BY total_paid DESC
LIMIT   20;
💡

Rule: Every column in SELECT that is not inside an aggregate function (COUNT, SUM, AVG…) must appear in GROUP BY.

Group by Multiple Columns

Monthly totals per vendor
SELECT
    vendor_name,
    DATE_TRUNC('month', invoice_date)  AS month,
    COUNT(*)                            AS invoices,
    SUM(amount)                          AS total
FROM   datasets.ds_your_table
GROUP BY vendor_name, DATE_TRUNC('month', invoice_date)
ORDER BY month, total DESC;

HAVING — Filter After Grouping

WHERE filters individual rows before grouping. HAVING filters groups after aggregation.

Vendors with total payments above 10 lakh
SELECT
    vendor_name,
    COUNT(*)     AS invoice_count,
    SUM(amount)  AS total_paid
FROM   datasets.ds_your_table
GROUP BY vendor_name
HAVING   SUM(amount) > 1000000   -- only groups where total > 10L
ORDER BY total_paid DESC;
Vendors with suspiciously high invoice counts
SELECT
    vendor_name,
    COUNT(*)    AS invoice_count,
    SUM(amount) AS total
FROM   datasets.ds_your_table
GROUP BY vendor_name
HAVING   COUNT(*) > 50             -- more than 50 invoices
ORDER BY invoice_count DESC;

Date & Time

Working with date columns — filtering by period, extracting parts, and computing differences.

Extracting Parts of a Date

EXTRACT and DATE_TRUNC
SELECT
    invoice_date,
    EXTRACT(YEAR  FROM invoice_date)   AS year,
    EXTRACT(MONTH FROM invoice_date)   AS month,
    EXTRACT(DAY   FROM invoice_date)   AS day,
    EXTRACT(DOW    FROM invoice_date)   AS day_of_week, -- 0=Sun, 6=Sat
    DATE_TRUNC('month', invoice_date)   AS month_start,
    DATE_TRUNC('quarter', invoice_date) AS quarter_start
FROM  datasets.ds_your_table;

Date Range Filtering

Filter by financial year, quarter, or month
-- Indian financial year FY 2024-25
SELECT * FROM datasets.ds_your_table
WHERE  invoice_date BETWEEN '2024-04-01' AND '2025-03-31';

-- A specific month
SELECT * FROM datasets.ds_your_table
WHERE  DATE_TRUNC('month', invoice_date) = '2024-12-01';

-- Last 90 days from today
SELECT * FROM datasets.ds_your_table
WHERE  invoice_date >= NOW() - INTERVAL '90 days';

Monthly Totals

Aggregate by month
SELECT
    DATE_TRUNC('month', invoice_date)  AS month,
    COUNT(*)                            AS invoice_count,
    SUM(amount)                          AS total_amount
FROM   datasets.ds_your_table
WHERE  invoice_date BETWEEN '2024-04-01' AND '2025-03-31'
GROUP BY DATE_TRUNC('month', invoice_date)
ORDER BY month;

Days Between Dates (Ageing)

Compute how old an invoice is
SELECT
    invoice_number,
    vendor_name,
    invoice_date,
    due_date,
    EXTRACT(DAY FROM AGE(due_date, invoice_date))  AS credit_days,
    EXTRACT(DAY FROM AGE(NOW(), due_date))          AS days_overdue
FROM  datasets.ds_your_table
WHERE due_date < NOW()
ORDER BY days_overdue DESC;
⚠️

Date stored as TEXT? Use TO_DATE(col, 'DD/MM/YYYY') to convert. For example: TO_DATE(invoice_date, 'DD-MON-YY') for dates like "15-Mar-24".

NULL Handling

NULL means "no value" or "unknown". NULL is not zero, not empty string — it's the absence of data. It requires special handling in SQL.

⚠️

Critical: amount = NULL never works — always use amount IS NULL. This is one of the most common SQL mistakes beginners make.

Testing for NULL

Find and count missing values
-- Rows where vendor name is missing
SELECT * FROM datasets.ds_your_table
WHERE  vendor_name IS NULL;

-- Rows where amount IS provided
SELECT * FROM datasets.ds_your_table
WHERE  amount IS NOT NULL;

-- Count nulls per column
SELECT
    COUNT(*)                              AS total_rows,
    COUNT(vendor_name)                    AS vendor_filled,
    COUNT(*) - COUNT(vendor_name)        AS vendor_missing,
    COUNT(*) - COUNT(amount)             AS amount_missing
FROM  datasets.ds_your_table;

COALESCE — Replace NULL with a Default

Substitute a value when NULL
SELECT
    COALESCE(vendor_name, 'Unknown Vendor')  AS vendor,
    COALESCE(amount, 0)                      AS amount,
    COALESCE(notes, description, 'No info') AS remarks -- tries each in order
FROM  datasets.ds_your_table;
Subqueries

A subquery is a query nested inside another query. It lets you answer more complex questions in a single statement.

Filter Using a Subquery

Transactions above the average amount
SELECT *
FROM   datasets.ds_your_table
WHERE  amount > (
    SELECT AVG(amount)
    FROM   datasets.ds_your_table
)
ORDER BY amount DESC;

Subquery in SELECT — Computed Column

Show each transaction vs. overall average
SELECT
    vendor_name,
    amount,
    (SELECT ROUND(AVG(amount), 2) FROM datasets.ds_your_table) AS avg_amount,
    amount - (SELECT AVG(amount) FROM datasets.ds_your_table)  AS deviation
FROM  datasets.ds_your_table
ORDER BY deviation DESC;
Joining Datasets

JOIN combines rows from two different tables based on a common column — for example, matching invoice data with a vendor master list.

ℹ️

In DataSense Pro, you can join any of your uploaded datasets. Both tables must be in the datasets schema. Use the Workbench left panel to find the full table names of each dataset.

INNER JOIN — Only Matching Rows

Match invoices with vendor master
SELECT
    inv.invoice_number,
    inv.amount,
    inv.invoice_date,
    vend.vendor_category,
    vend.pan_number
FROM  datasets.ds_invoices_table  inv
JOIN  datasets.ds_vendor_master    vend
  ON  UPPER(TRIM(inv.vendor_name)) = UPPER(TRIM(vend.vendor_name))
ORDER BY inv.amount DESC;

LEFT JOIN — Keep All Rows from Left Table

Invoices with no vendor master record
SELECT
    inv.invoice_number,
    inv.vendor_name,
    inv.amount,
    vend.pan_number  -- will be NULL if no match
FROM      datasets.ds_invoices_table  inv
LEFT JOIN datasets.ds_vendor_master    vend
  ON  UPPER(TRIM(inv.vendor_name)) = UPPER(TRIM(vend.vendor_name))
WHERE vend.vendor_name IS NULL   -- no matching master record — flag these!
ORDER BY inv.amount DESC;
Audit Toolkit

Ready-to-copy SQL queries for the most common audit and investigation scenarios. Replace ds_your_table with your actual table name from the left panel.

✅

These queries are safe — they only read data. Click Copy on any query, paste it into the Workbench editor, replace the table name, and run.

1. Finding Duplicate Transactions

Duplicate payments or invoices are one of the most common fraud and error types in accounts payable.

🔴 High Risk
Exact duplicate rows
SELECT
    vendor_name,
    amount,
    invoice_date,
    COUNT(*)  AS occurrences
FROM   datasets.ds_your_table
GROUP BY vendor_name, amount, invoice_date
HAVING   COUNT(*) > 1
ORDER BY occurrences DESC, amount DESC;
Same amount to same vendor on different dates
SELECT
    vendor_name,
    amount,
    COUNT(DISTINCT invoice_date)  AS on_different_dates,
    SUM(amount)                    AS total_paid
FROM   datasets.ds_your_table
GROUP BY vendor_name, amount
HAVING   COUNT(DISTINCT invoice_date) > 1
ORDER BY total_paid DESC;

2. Round Number Analysis

Humans fabricating figures tend to choose round numbers. Naturally occurring amounts are rarely perfectly round.

🔴 High Risk
Transactions that are exact multiples of 1000
SELECT
    vendor_name,
    amount,
    invoice_date
FROM   datasets.ds_your_table
WHERE  amount % 1000 = 0          -- divisible by 1000
  AND  amount > 0
ORDER BY amount DESC;
Summary: what % of transactions are round numbers?
SELECT
    COUNT(*)                                          AS total,
    SUM(CASE WHEN amount % 1000 = 0 THEN 1 ELSE 0 END) AS round_thousands,
    SUM(CASE WHEN amount % 10000 = 0 THEN 1 ELSE 0 END) AS round_ten_thousands,
    ROUND(
        100.0 * SUM(CASE WHEN amount % 1000 = 0 THEN 1 ELSE 0 END) / COUNT(*), 1
    )                                                  AS round_pct
FROM  datasets.ds_your_table
WHERE amount > 0;

3. Just-Below-Threshold Payments

Employees sometimes split payments just below approval thresholds (e.g. ₹49,999 when the threshold is ₹50,000).

🔴 High Risk
Payments between 48,000 and 50,000 — below a 50K threshold
SELECT
    vendor_name,
    amount,
    invoice_date,
    invoice_number
FROM   datasets.ds_your_table
WHERE  amount BETWEEN 48000 AND 49999
ORDER BY amount DESC;

4. Vendor Concentration

Identifies vendors that account for a disproportionate share of total payments.

🟡 Medium Risk
Top 10 vendors by total amount
SELECT
    vendor_name,
    COUNT(*)              AS invoice_count,
    ROUND(SUM(amount), 2) AS total_paid,
    ROUND(
        100.0 * SUM(amount) /
        (SELECT SUM(amount) FROM datasets.ds_your_table),
        2
    )                       AS pct_of_total
FROM   datasets.ds_your_table
GROUP BY vendor_name
ORDER BY total_paid DESC
LIMIT   10;

5. Missing Value Audit

Incomplete records — missing vendor names, invoice numbers, or amounts — are an immediate red flag.

🟡 Medium Risk
Null value summary for every key column
SELECT
    COUNT(*)                                               AS total_rows,
    COUNT(*) - COUNT(vendor_name)    AS missing_vendor,
    COUNT(*) - COUNT(amount)          AS missing_amount,
    COUNT(*) - COUNT(invoice_date)   AS missing_date,
    COUNT(*) - COUNT(invoice_number) AS missing_inv_num
FROM  datasets.ds_your_table;

6. Weekend & Holiday Transactions

Transactions on weekends or public holidays may indicate bypassed controls.

🟡 Medium Risk
Transactions posted on weekends
SELECT
    vendor_name,
    amount,
    invoice_date,
    CASE EXTRACT(DOW FROM invoice_date)
        WHEN 0 THEN 'Sunday'
        WHEN 6 THEN 'Saturday'
    END AS day_name
FROM  datasets.ds_your_table
WHERE EXTRACT(DOW FROM invoice_date) IN (0, 6)  -- 0=Sunday, 6=Saturday
ORDER BY amount DESC;

7. Period-End Concentration

High volumes at month-end or year-end can indicate rushed postings, back-dating, or window dressing.

🔴 High Risk
Last 3 days of each month vs. rest of month
SELECT
    DATE_TRUNC('month', invoice_date)             AS month,
    SUM(CASE WHEN
        EXTRACT(DAY FROM
            (DATE_TRUNC('month', invoice_date) + INTERVAL '1 month') -
            invoice_date
        ) <= 3
        THEN amount ELSE 0
    END)                                           AS last_3_days,
    SUM(amount)                                    AS month_total,
    ROUND(100.0 * SUM(CASE WHEN
        EXTRACT(DAY FROM
            (DATE_TRUNC('month', invoice_date) + INTERVAL '1 month') -
            invoice_date
        ) <= 3
        THEN amount ELSE 0
    END) / NULLIF(SUM(amount),0), 1)             AS last3_pct
FROM  datasets.ds_your_table
GROUP BY DATE_TRUNC('month', invoice_date)
ORDER BY month;

8. Sequential Number Gaps

Gaps in invoice or voucher sequences may indicate deleted or missing documents.

🔵 Reference
Find gaps in a numeric invoice sequence
WITH numbered AS (
    SELECT
        invoice_number::BIGINT                          AS inv_num,
        LEAD(invoice_number::BIGINT) OVER
            (ORDER BY invoice_number::BIGINT)           AS next_num
    FROM  datasets.ds_your_table
    WHERE invoice_number ~ '^[0-9]+$'               -- numeric only
)
SELECT
    inv_num         AS last_before_gap,
    next_num        AS first_after_gap,
    next_num - inv_num - 1  AS missing_count
FROM  numbered
WHERE next_num - inv_num > 1
ORDER BY missing_count DESC;
